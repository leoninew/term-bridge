# Shell Command Execution
最后修改时间: 2026-07-10 13:25:56

Review status: Accepted

## Background

当前新建 Web 终端会话会在前端把命令输入按空白字符拆分为参数数组，再由 Agent 直接启动可执行文件。这会破坏引号、管道、重定向、变量展开等 Shell 语义，且浏览器 UA 推断的默认命令不应决定 Agent 所在机器的执行策略。

CLI `termbridge exec -- <command> [args...]` 与 Web 新建会话同样需要明确记录启动、关键阶段和失败上下文；项目已有结构化日志基础设施，应沿用而不是引入独立日志机制。

## Goal

1. 将 Web 新建会话的命令输入视为原始 command text；前端、HTTP/Proto 和持久化层均不得按空白拆分、重写或解释。
2. 仅在 PTY 基础设施启动边界使用第三方 argv parser，将原始文本转换为直接进程启动所需的 executable 与 args；不引入 Shell 包装、默认 Shell 选择、Shell 语义或环境变量展开。
3. 拒绝未被引号包裹的 Shell 控制符，避免用户误以为管道、重定向或条件连接会被执行。
4. 保留会话的原始命令文本，供会话展示、诊断及重跑使用。
5. 为 CLI `exec` 与 Web 新建会话的执行生命周期补充关键结构化日志，尤其保证失败时包含可定位的上下文，同时不记录命令标准输出或可能包含敏感内容的环境变量值。

## Non-goal

- 不建立命令白名单、预置命令库、参数解析 UI 或 Shell 包装层。
- 不支持 Shell 语法、环境变量展开、命令替换或管道/重定向。
- 不添加远程命令执行能力或改变云端 tunnel 的授权模型。
- 不记录终端用户输入、命令输出全文或环境变量值。
- 不在本次变更中重做现有日志框架、日志格式或日志文件配置。

## User scenarios

1. 用户新建会话并输入 `ccs list --filter "my project"`，前端、API 和持久化完整保留原文；PTY 启动边界将其解析为 `ccs` 和三个参数，并直接启动该进程。
2. 用户输入交互式程序时，会话保持交互式，直至该程序退出。
3. 用户输入 `ccs list | findstr active` 等未引号包裹的 Shell 控制符时，系统以可定位的 usage error 拒绝，而非将其当作普通参数或执行 Shell。
4. 命令不可启动或进程异常退出时，开发者能从结构化日志中关联会话/执行来源、工作目录、命令安全摘要、生命周期阶段、错误和退出信息。

## Acceptance

- [ ] Web 创建请求传递未被参数拆分的原始命令文本；前端仅拒绝空白命令。
- [ ] 仅 PTY 基础设施启动边界解析原始文本为 executable 与 args；不引入 Shell 包装、默认 Shell 选择、Shell 语义或环境变量展开。
- [ ] `ccs list --filter "my project"` 解析为 `ccs`、`list`、`--filter`、`my project` 并直接启动。
- [ ] 未被引号包裹的 Shell 控制符（包括 `|`、`&&`、`;`、`>`、`<`）被拒绝并返回 usage error。
- [ ] 新建会话、展示和重跑均使用持久化的原始命令文本。
- [ ] 原始命令文本沿用既有持久化与 Proto 能力传输；本次不引入迁移、旧字段回退、双写或适配层。
- [ ] CLI `exec` 与 Web 会话创建/启动/启动失败/进程退出均通过现有结构化 logger 输出关键生命周期日志。
- [ ] 失败日志至少包含执行来源、会话标识（存在时）、工作目录、阶段、错误；退出日志包含退出码及最终状态。
- [ ] 日志不得写入环境变量值、完整终端 I/O 或未经审查的敏感载荷。
- [ ] 现有会话创建、重跑、历史记录与 WebSocket 终端交互行为保持可用。

## Decisions

- 原始命令文本是用户意图、HTTP/Proto 载荷和持久化事实来源；PTy 启动边界是唯一允许将该文本解析为 executable 与 args 的位置。
- 使用 `github.com/mattn/go-shellwords` 作为 PTY 基础设施的 argv parser，并显式关闭环境变量展开和反引号解析。
- 不支持 Shell 控制符；未被引号包裹的 `|`、`&&`、`;`、`>`、`<` 一律拒绝。
- 原始命令文本使用项目已有的持久化和 Proto 传输能力；不做旧结构兼容、双写、数据迁移或适配层。
- 日志沿用项目既有 `slog`/日志配置与既有字段风格；新增日志只覆盖可操作的生命周期边界和失败点。

## Risk

- 参数引号规则由第三方 argv parser 定义，必须以覆盖空格、引号、转义与控制符的测试固定行为。
- 原始命令可能包含敏感参数；日志必须只记录经审查的安全摘要，不能原样输出命令文本。
- 这是破坏性替换：旧的 command/args 持久化记录不在本次变更兼容范围内。
