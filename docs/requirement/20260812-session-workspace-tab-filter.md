# 会话目录 Tab 联动
最后修改时间: 2026-08-12 16:21:19

Review status: Accepted

## Background

会话页面的左侧树按会话目录（workspace）组织会话，右侧工作台目前将所有已打开会话混合展示为同一组 tab，用户难以聚焦当前目录的终端。

## Goal

点选左侧会话节点时，右侧仅展示该节点所属会话目录中已打开的 tab；该目录内的 tab 仍可单独关闭、批量关闭和排序。

## Non-goal

- 不关闭、不删除或隐藏性移除其他会话目录的全局已打开 tab。
- 不改变左侧树的目录展开、搜索、排序或会话生命周期操作。
- 不改变后台终端连接保活策略。

## User scenarios

1. 用户点选目录 A 中的会话，右侧切换到目录 A，并只显示目录 A 的已打开 tab。
2. 用户在目录 A 关闭 tab，目录 B 的已打开 tab 保留，且关闭后仍停留在目录 A 的可见 tab 范围内选择下一个 tab。
3. 用户切换至目录 B 的会话，目录 B 先前打开的 tab 再次显示，目录 A 的 tab 仍被保留。

## Acceptance

- 左侧会话节点选择会同步当前 tab 筛选目录。
- 右侧 tab 条、tab 菜单和批量 tab 操作仅针对当前筛选目录的已打开 tab。
- 右侧 tab 标题只显示会话名称，不重复显示当前已筛选的目录名称。
- 关闭当前活动 tab 时，优先选择同一筛选目录中相邻的未关闭 tab；没有可选 tab 时不切换到其他目录。
- 所有全局已打开的运行会话继续参与终端保活，目录筛选不能导致非当前目录终端被误关闭。
- 前端类型检查与相关 Vitest 用例通过。

## Open questions

暂无需要用户确认的未决事项。

## Decisions

- 将当前筛选目录状态保留在 `SessionsPageShell`，不写入路由或持久化存储。
- `useWorkbenchStore` 继续维护完整的全局 tab 列表；组件接收单独的可见 tab 列表和全量终端 tab 列表。

## Risk

- 筛选目录最后一个 tab 关闭时，右侧会显示无 tab 状态；这是为了不跨目录自动切换，符合当前聚焦目录的约束。
