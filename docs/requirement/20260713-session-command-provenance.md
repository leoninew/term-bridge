# 会话命令来源持久化与状态栏展示

最后修改时间: 2026-07-13 11:00:23

Review status: Accepted

## Flow mode / Stage

轻量模式 / light；需求 / Requirement 已接受，当前进入实现 / Implementation。

## Background

`/sessions` 底部状态栏原先只能显示 Session 的原始命令快照。快捷方式或直接命令来源仅存在创建、编辑会话模态窗的内存状态，刷新、重新登录或通过其他客户端访问会话时无法恢复。

## Goal

1. 持久化会话当前命令是由快捷方式还是直接命令配置。
2. 快捷方式来源保存 ID 与名称快照，使快捷方式后续改名、改命令或删除后，既有会话的来源展示仍准确。
3. 状态栏按可靠的持久来源展示快捷方式名称或直接命令，并为历史旧数据提供中性回退。

## Non-goal

1. 不通过命令文本匹配当前快捷方式来推断来源。
2. 不建立 Session 到 Shortcut 的外键或动态关联。
3. 不改变会话实际执行、rerun、命令快照或快捷方式排序语义。
4. 不修改数据库表结构：来源快照存入现有 `command_json` / `CommandRecord`。

## User scenarios

1. 用户以快捷方式创建会话；刷新或重新登录后，状态栏仍显示选择时的快捷方式名称及原始命令。
2. 用户通过直接命令创建或编辑会话；状态栏显示“直接命令”及原始命令。
3. 用户把停止会话改为另一个快捷方式；新配置覆盖此前来源快照。
4. 用户仅修改会话名称；现有命令来源快照保持不变。
5. 用户删除或改名快捷方式；历史会话仍显示保存时的快捷方式名称。
6. 旧会话没有来源字段；状态栏显示“启动命令”，不作错误归因。

## Acceptance

- [ ] 创建和更新会话 API 接受并校验命令来源与快捷方式快照组合。
- [ ] `SessionSummary` 返回命令来源和快捷方式快照。
- [ ] 快捷方式、直接命令和旧会话分别获得准确状态栏展示。
- [ ] 快捷方式来源缺少 ID 或名称、直接命令携带快捷方式快照、来源字段不随命令更新一起提交等无效组合均被拒绝。
- [ ] 旧 JSON 无来源字段仍可读取且回退为未知来源。
- [ ] Local 与 Cloud 经由同一生成 API 契约透传数据。
- [ ] 关键 Go 与 Web 测试、类型检查、lint 与格式检查通过。

## Decisions

- 来源使用 `shortcut`、`command` 或空值（历史未知）表示。
- `shortcut_id_snapshot` 与 `shortcut_name_snapshot` 是不可变展示快照，无外键关联。
- 命令来源字段属于 Session 当前命令配置；每次实际更新命令时覆盖，单独改名称不覆盖。
- 每次 rerun 复制当前 `CommandRecord` 到既有 `session_runs.command_json` 快照。

## Risk

- 本次扩展 proto 后，所有前端 SessionSummary fixture 必须包含新增字段。
- 请求来源组合校验不能让旧会话仅改名称时失败；无命令来源更新时必须保留旧快照。
- 状态栏对空来源只能显示中性文案，不能误标为直接命令。
