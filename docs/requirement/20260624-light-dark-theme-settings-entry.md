# 浅暗色主题与左下角设置入口需求
最后修改时间: 2026-06-24 21:29:44

Review status: Accepted

## Background

当前产品需要补齐基础外观偏好能力，让用户可以在 Web UI 中切换浅色 / 暗色主题，并在主界面左下角提供一个稳定可发现的设置入口。用户已补充当前前端技术栈为 `reka-ui` + `tailwind css v4`，后续实现应优先沿用该组合与现有项目约定。

## Goals

1. 提供浅色 / 暗色主题切换能力，仅支持 `light` / `dark` 两种主题。
2. 默认主题为 `dark`。
3. 在主界面左下角增加设置入口，作为进入设置相关能力的统一入口。
4. 设置入口与主题切换 UI 应符合现有界面风格，并基于 `reka-ui` 组件能力与 `tailwind css v4` 样式体系实现。
5. 主题状态应在当前 Web UI 中生效，覆盖主要页面区域和常用交互状态。
6. 在 `web/src/store` 下添加 storage 封装，通过 `localStorage` 缓存主题设置，避免用户刷新后丢失明确选择。
7. 主题切换交互与代码组织参考现有语言切换实现。

## Non-goals

1. 不重做整体视觉设计系统或重构全部页面布局。
2. 不引入 `reka-ui` 与 `tailwind css v4` 之外的新 UI 组件体系或主题框架，除非实现阶段发现现有依赖无法满足需求并先报告。
3. 不扩展完整设置中心的全部业务配置项；本次只要求新增入口并承载主题相关设置。
4. 不改变后端业务协议、终端会话核心逻辑或认证流程。
5. 不要求在本阶段实现多主题品牌皮肤、主题市场或自定义颜色编辑器。
6. 不支持 `system` / 跟随系统主题。
7. 终端区域跟随主题切换；包括终端外围容器与 xterm 内部主题色都应适配 `light` / `dark`。

## User scenarios

1. 用户打开应用后，可以在左下角看到设置入口，并能点击进入或展开设置相关界面。
2. 用户在设置界面中选择浅色主题后，界面切换为浅色外观。
3. 用户在设置界面中选择暗色主题后，界面切换为暗色外观。
4. 用户刷新页面或重新进入 Web UI 后，之前明确选择的主题仍通过 `localStorage` 恢复。
5. 如果用户尚未选择主题，系统默认使用暗色主题。
6. 用户切换主题时，体验和信息层级应参考现有语言切换。

## Acceptance criteria

1. 左下角存在清晰、可点击、不会遮挡核心操作区域的设置入口。
2. 设置入口可打开设置 UI，设置 UI 中至少包含浅色 / 暗色主题切换项。
3. 主题切换后，页面主要背景、文字、边框、卡片 / 面板、按钮、输入控件、菜单 / 弹层等关键视觉元素能够正确适配浅色与暗色。
4. 主题切换不应破坏现有路由、会话列表、终端区域和主要交互流程。
5. 实现使用项目现有前端栈，优先采用 `reka-ui` 提供的无样式 / 可访问交互组件，并使用 `tailwind css v4` 表达样式与主题 token。
6. 在 `web/src/store` 增加 storage 封装，使用 `localStorage` 保存主题设置；刷新后恢复用户选择。
7. 默认主题为 `dark`；不存在主题缓存或缓存值非法时回退到 `dark`。
8. 只提供 `light` / `dark` 选项，不提供 `system`。
9. 终端区域跟随主题切换；xterm 背景、前景、光标、选区等核心颜色应与当前主题协调。
10. 不出现明显的白底黑字 / 黑底黑字、低对比、弹层主题错位或闪烁到不可用状态的问题。

## Decisions

1. 本任务采用标准模式 / standard。
2. 本任务是新任务，创建独立 requirement 文档，不沿用历史需求文档。
3. 前端技术栈按用户补充确认为 `reka-ui` + `tailwind css v4`。
4. 主题选项只支持 `light` / `dark`。
5. 默认主题为 `dark`。
6. 主题偏好通过 `web/src/store` 下新增 storage 封装写入 `localStorage`。
7. 主题切换参考语言切换实现。
8. 终端区域跟随主题切换。
9. 用户已要求进入 Plan / 计划阶段，因此本 requirement 标记为 `Accepted`。

## Risks / Assumptions

1. 假设现有前端已经具备或可以低成本接入 `reka-ui` 组件；若实际依赖或封装方式不同，Plan 阶段需要调整。
2. 假设 `tailwind css v4` 的主题表达可以与现有 CSS 结构兼容；如果现有样式大量硬编码颜色，可能需要比预期更多的样式梳理。
3. 左下角设置入口可能与现有导航、状态栏或会话操作区域产生布局冲突，需要实现前检查现有页面结构。
4. 终端渲染区域通常有独立配色体系，本任务明确要求终端区域跟随主题切换；实现时需通过 xterm 主题配置或等价机制更新终端内部颜色，避免只切换外围容器导致观感割裂。
