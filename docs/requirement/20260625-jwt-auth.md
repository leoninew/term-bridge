# JWT 认证替换随机 token

最后修改时间: 2026-06-25 16:30:00

## Background

当前 TermBridge-go 使用随机 32-byte hex 字符串作为 `termbridge_gateway_session` cookie 进行认证。服务端用内存 `map[string]time.Time` 存储 session，无 TTL 机制，服务重启即丢失全部登录状态。

pomelo-orbit（同 workspace 参考项目）已采用 JWT（HS256）+ Bearer token 方案，认证信息通过 `Authorization` 头传递，服务端无状态可验证。

## Goal

将认证机制从随机 token + 内存 session 替换为 JWT，参考 pomelo-orbit 的实现方式。

## Non-goal

- 不实现用户权限体系（RBAC）
- 不实现 token refresh / 续期机制
- 不实现登录历史记录
- 不向后兼容旧 cookie 认证

## User scenarios

1. 用户访问 `/login` 页面，输入 username/password，前端 POST `/api/login`。
2. 后端校验通过后返回 `{"access_token": "<jwt>", "token_type": "bearer"}`。
3. 前端将 token 存储在 localStorage（`termbridge_gateway_token`），后续请求通过 `Authorization: Bearer <token>` 头传递。
4. 后端中间件从 header 解析 JWT，验证签名和有效期，通过则放行。
5. token 过期后前端收到 401，跳转回 `/login` 页面。

## Frontend pattern (参考 pomelo-orbit)

- **Store**: `useGatewayStore` 管理 `token`（localStorage）、`authenticated`、`username`
- **API 层**: `authLogin()` 返回 `{ access_token, token_type }`，`authMe()` 返回 `{ authenticated, username }`
- **请求拦截器**: `apiClient.interceptors.request.use` 从 store 读取 token，设置 `Authorization: Bearer` 头
- **响应拦截器**: 401 时清除 token、跳转 `/login`
- **Token 存储**: localStorage key = `termbridge_gateway_token`

## Acceptance

- [ ] `POST /api/login` 返回格式变为 `{"access_token": "...", "token_type": "bearer"}`
- [ ] 受保护端点（`/api/me`、`/api/devices`、`/api/logout` 等）通过 `Authorization: Bearer` 头验证
- [ ] JWT 有效期 24 小时
- [ ] JWT 签名算法 HS256（HMAC-SHA256）
- [ ] 密钥通过配置文件 / 环境变量注入
- [ ] 旧 `termbridge_gateway_session` cookie 认证完全移除
- [ ] 前端 `LoginView.vue` 和 `gateway.ts` store 适配新认证流程
- [ ] 服务端重启后已签发 token 仍有效（只要未过期）

## Decisions

- 采用 HS256（HMAC-SHA256），与 pomelo-orbit 一致，不引入非对称算法
- Token 通过 `Authorization: Bearer` 头传递，不依赖 cookie
- 前端存储使用 localStorage（与 pomelo-orbit 一致）
- 不实现 refresh token，过期即重新登录
- 新增 `JWTConfig`，字段名 `jwt.secret_key`，需手动配置，不自动生成

## Risk

- 密钥泄露会导致任意用户伪造 token，生产环境必须配置强密钥
- 前端存储 localStorage 存在 XSS 风险，但当前项目已有 XSS 风险面，不因此次变更引入新攻击面
- 不向后兼容意味着部署后旧客户端会立即 401，需确保前后端同步部署
