# 工作区会话拖拽排序体验优化
最后修改时间: 2026-07-13 15:35:52

Review status: Accepted

## Background

工作区侧边栏已具备工作区排序和工作区内会话列表的排序基础。当前任务聚焦于明确每个工作区目录内的会话拖拽排序边界，并改善拖拽相关的视觉反馈与交互体验，使用户能清楚地区分可拖拽对象、当前拖拽状态和操作不可用状态。

## Goal

1. 为工作区侧边栏的会话排序配置统一、明确的 Sortable 状态样式：拖拽源（ghost）、已选中项（chosen）和拖拽中项（dragging），并改善非拖拽状态下的交互反馈。
2. 让每个工作区目录下的会话都支持独立拖拽排序。
3. 确保一次会话排序仅影响其所属工作区目录，不改变其他目录下会话的顺序，也不允许跨目录移动会话。
4. 保持现有会话选择、编辑、停止、搜索和工作区排序行为可用。

## Non-goal

- 不新增跨工作区移动会话的能力。
- 不改变工作区或会话排序的后端数据模型与 API 契约，除非现有实现无法满足独立目录排序。
- 不为终端工作台标签页或快捷方式卡片扩展本需求中的样式与 UX 范围。
- 不改变会话创建、删除、生命周期管理或搜索结果语义。

## User scenarios

1. 用户展开任意工作区目录后，可以在该目录内拖拽一个会话到目标位置，并立即看到该目录内的新顺序。
2. 用户展开多个工作区目录后，对其中一个目录排序，不会干扰其他目录中的会话顺序。
3. 用户从会话行的非按钮区域开始拖拽时，能清楚看出拖拽源（ghost）、已选中项（chosen）、拖拽中项（dragging）和可放置位置；编辑、停止等按钮不应意外触发拖拽。
4. 用户在搜索会话时，排序交互保持禁用或采用与现有行为一致的安全限制，避免对过滤结果造成错误排序。
5. 排序保存失败时，界面恢复到可靠顺序并向用户保留现有的错误处理体验。

## Acceptance

- 每个已展开工作区目录的会话列表均可独立拖拽排序。
- 单个目录内的会话重排只提交并更新该目录对应的会话顺序；其他目录的会话顺序不变。
- 会话不能通过拖拽进入其他工作区目录。
- 工作区排序功能和现有会话点击、编辑、停止操作持续可用，且操作按钮不会作为拖拽起点。
- 侧边栏为会话拖拽提供统一、清晰的 ghost、chosen、dragging 和放置目标视觉反馈；搜索导致排序不可用时，用户不会获得可拖拽的误导性反馈。
- 不新增独立拖拽手柄：会话行的非交互控件区域可直接拖拽，编辑、停止等按钮不会成为拖拽起点。
- 现有排序持久化、服务端规范顺序覆盖和失败回滚语义保持正确，并补充与本次独立目录排序相关的测试。

## Open questions

- 暂无需要用户确认的未决事项。

## Decisions

- 会话排序的边界是单个工作区目录；不同目录间互不影响。
- 仅在非搜索状态下允许排序，沿用当前侧边栏对过滤结果的保护策略。
- UX 改进限定在工作区侧边栏的会话排序场景，不扩展为全站拖拽视觉规范。
- 不使用独立拖拽手柄；会话行的非交互控件区域直接作为拖拽起点，行内按钮必须排除在拖拽起点之外。
- 使用 Sortable 的 `ghostClass`、`chosenClass` 和 `dragClass` 配置统一承载拖拽状态样式，而非依赖默认视觉表现。

## Risk

- 嵌套拖拽列表可能使父级工作区排序与子级会话排序的事件、手柄或占位反馈相互干扰；实现需要明确隔离两个 Sortable 实例。
- 拖拽事件应只在真实顺序变化时触发持久化，避免无效请求或错误覆盖其他目录状态。
- UI 层局部重排必须与 store 的乐观更新、服务端返回结果和失败回滚保持一致。
