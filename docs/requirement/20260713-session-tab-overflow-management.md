# 会话 Tab 溢出与清理

最后修改时间: 2026-07-13 17:57:19

Review status: Accepted

## Flow mode / Stage

轻量模式 / light；需求 / Requirement 已接受，当前进入验证 / Verification。

## Background

`/sessions` 的 Tab 条目前承担所有已打开会话的访问入口。Tab 数量增加时，用户需要横向滚动逐个查找，或先关闭 Tab 再从左侧树重新打开，无法有效管理临时访问的会话上下文。

同时，前端 Tab 与实际后端 Session 是不同对象：整理不再进行中的已打开 Tab 不应停止终端；关闭运行中的后端会话则必须调用后端接口。菜单需要明确表达两种操作的范围和副作用。

## Goal

保留现有 Tab 拖拽排序、单项关闭、状态主题色和终端历史加载行为，并在 Tab 条右侧提供始终可见的下拉入口：

1. 列出全部已打开 Tab 的溢出列表。
2. 提供“关闭已停止标签页”操作，整理已打开的非进行中 Tab。
3. 提供“关闭运行中会话”操作，停止用户从候选 tree 中选择的运行中会话。

## Non-goal

1. 不搜索、筛选、排序、固定 Tab，也不在溢出项中增加单独关闭操作。
2. 不改变 Tab 拖拽排序或单项关闭行为。
3. “关闭已停止标签页”不调用后端停止或删除接口。
4. 不新增后端批量关闭 API，也不并发调用多个关闭接口。
5. 不关闭任何已在 Tab 中打开的运行会话。

## User scenarios

1. 用户打开很多会话后，仍可通过固定的右侧菜单查看并切换任何已打开 Tab。
2. 用户选择“关闭已停止标签页”后，关闭当前已打开且生命周期为 `stopped` 或 `failed` 的 Tab；运行中的和无法解析的 Tab 保留，后端 Session 不受影响。
3. 用户选择“关闭运行中会话”后，从右侧向左打开 Drawer，按左侧导航栏顺序查看含有运行中会话的工作区 tree；仅展示运行中会话，未在当前 Tab 打开的会话默认勾选，已打开会话默认不勾选，用户可自行选择后确认。
4. Drawer 中展示的运行中会话 tree 既是候选展示，也是用户选择的待关闭会话数据源；关闭中每个成功结果立即反映到会话树，任一关闭失败时不再继续后续请求，最终刷新后保留 Drawer，以便用户查看仍可操作项并重试。
5. Tab 数量过多时不显示横向滚动条，但保持横向滚动、拖拽和固定右侧菜单。
6. 批量移除当前 Tab 时，系统选择其右侧最近的剩余 Tab；没有右侧项时选择左侧最近项，并只加载最终替代会话一次。

## Decisions

- 菜单第一项为“关闭已停止标签页”，其说明为“关闭当前已打开、但不再进行中的标签页。”；它只管理前端 Tab。
- 菜单第二项为“关闭运行中会话”，其说明为“选择要关闭的运行中会话；未打开的会话默认勾选。”；它实际调用既有后端关闭接口。
- Drawer 使用仅含运行中会话的工作区树，使用 `(workspaceId, sessionId)` 复合身份识别 session；未打开 running 节点默认勾选，已打开 running 节点由用户决定，展示 tree 同时是选择数据源。
- 后端关闭按用户从 Drawer tree 选择的运行中会话顺序 `await` 执行，不使用新的批量接口或并发 Promise；每次成功立即应用响应，会在 `finally` 中执行一次刷新。
- 批量关闭已停止 Tab 采用原子状态变更，不循环调用单项关闭，避免中间 Tab 切换和重复历史加载。
- 生命周期判断由页面层基于权威 session tree 完成；workbench store 仅管理 Tab 状态和最终激活回退。

## Risk

- 下拉按钮如果放进可拖拽或可滚动容器，会随 Tab 移动或干扰拖拽；必须作为 Tab 列表右侧 sibling。
- 批量移除当前 Tab 时若逐项关闭，会产生错误回退与多次历史请求；必须一次计算最终替代 Tab。
- 会话树刷新期间可能无法解析个别 Tab；未知项不能被误判为终态并关闭。
- Drawer 打开后外部操作可能改变 Session 状态、打开 Tab 或删除会话；刷新后的工作区 tree 必须保持完整展示，已消失节点不能请求关闭，且不应重置用户已经修改的勾选。
- 隐藏 Tab 滚动条不得将可滚动容器改为裁剪，或让固定菜单进入可拖拽容器。
- 关闭序列中出现网络或后端错误时，后续 Session 必须保持未操作，且刷新失败不能掩盖原始关闭错误。
