# 快捷方式自定义图标、状态与标签
最后修改时间: 2026-07-14 22:45:05

Review status: Accepted

## Background

当前快捷方式只包含名称、命令和描述，且所有快捷方式都会出现在新建、编辑会话时的命令来源选择器中。随着快捷方式数量和用途增加，用户需要为快捷方式补充可识别的图标、可用状态和轻量的分类能力，同时确保已禁用的快捷方式不会被新建或编辑会话继续采用。

现有快捷方式数据由 Agent 的 `shortcuts` 表持久化，并经 protobuf、Agent HTTP API 与云端设备中继提供给前端。分组不需要独立实体或后端分组表。

## Goal

1. 为每个快捷方式增加以下可持久化属性：
   - `icon`：字符串类型的图标占位字段，当前只为后续图标库管理预留，不在本期实现编辑、呈现或业务使用。
   - `enabled`：快捷方式是否可被会话创建/编辑选择；新建快捷方式和既有数据默认启用。
   - `tags`：零到多个自由文本标签，以 JSON 数组存储在快捷方式单列中；不创建标签表、标签 API 或标签生命周期管理。
   - `last_used_at`：可空的最后使用时间字段，为未来能力预留；本期仅持久化并随快捷方式响应返回，不接受客户端写入，也不采集、展示、排序或筛选。
2. 快捷方式管理页支持维护启用状态和多个标签，在卡片上呈现标签与禁用状态。
3. 前端通过 Pinia 标签 store 从当前已加载快捷方式的标签集合去重归纳可用标签；管理页在卡片上方提供工具条与控件，按标签过滤快捷方式。
4. 新建和编辑会话的快捷方式选择器只展示启用的快捷方式；标签应可展示并参与搜索。
5. 后端在会话创建或编辑请求指定快捷方式来源时，也必须拒绝不存在或已禁用的快捷方式，避免旧客户端、直接 API 请求或并发状态变化绕开前端限制。

## Non-goal

- 本期不实现 `icon` 的编辑器控件、前端呈现、会话选择器展示或任何业务逻辑；仅预留可持久化字符串字段。
- 本期不建设图标库、图标上传、图片 URL、任意 SVG、图标安全净化或图标资产管理。
- 不建设快捷方式分组表、分组 CRUD、空分组、分组排序、分组权限或跨设备共享分组。
- 不将全局快捷方式排序改为按分组排序；现有 `sort_order` 保持设备内全局排序。
- 不修改已有会话的历史快捷方式快照；已存在的会话继续使用其命令与名称快照。
- 不要求禁用快捷方式从快捷方式管理页删除或隐藏。
- 本期不在创建或编辑会话成功后写入 `last_used_at`，也不提供请求字段、前端展示、排序或筛选行为。

## User scenarios

1. 系统为每个快捷方式持久化 `icon` 字符串占位值，为后续图标库管理保留兼容的数据位置；本期不在界面中编辑或展示它。
2. 用户创建或编辑快捷方式时填写可选标签，并选择启用或禁用；保存后重新加载仍保留这些可用属性。
3. 用户在快捷方式管理页通过顶部工具条选择一个标签，只查看匹配的快捷方式；清除过滤后恢复全部快捷方式。
4. 用户禁用一个快捷方式后，该卡片仍在管理页显示，具有明确的禁用视觉状态；新建、编辑会话时的快捷方式选择器不再列出它，也不会将它作为默认选择。
5. 用户或旧客户端尝试使用已禁用快捷方式的 Id 创建或编辑会话时，服务端返回业务校验错误，不创建或更新会话。
6. 已使用后来被禁用快捷方式的历史会话仍可显示其既有快捷方式名称快照；用户编辑该会话时，不能重新选择该禁用快捷方式。

## Acceptance

- [ ] protobuf、API、领域模型、SQLite/MySQL 迁移和仓储读写均完整传递 `icon`、`enabled`、`tags` 与 response-only 的 `last_used_at`；字段为向后兼容的新增字段。
- [ ] 数据库升级后，已有快捷方式均保持启用；新建快捷方式默认启用。
- [ ] 空白 `icon` 与空白标签按可选元数据处理；标签去除首尾空白、空值和精确重复项，名称、命令和描述的既有规范化行为不回归。
- [ ] `icon` 字符串字段在 protobuf、API、领域模型、SQLite/MySQL 迁移和仓储读写中向后兼容地预留，但本期不在编辑器、卡片或会话选择器中实现其交互或呈现。
- [ ] 快捷方式编辑器可编辑启用状态与标签；卡片显示标签和禁用状态。
- [ ] 管理页可通过卡片上方工具条按标签过滤，过滤不破坏已有全局拖拽排序语义。
- [ ] 新建、编辑会话仅接收启用的快捷方式集合：禁用项不展示、不参与搜索、不被自动选为默认项。
- [ ] 后端拒绝以禁用或不存在的快捷方式作为命令来源的创建、编辑会话请求；启用快捷方式不受影响。
- [ ] 本地与云端路径行为一致，云端设备中继不会丢失新增字段或绕过状态校验。
- [ ] 覆盖模型/服务/仓储/迁移/API 与前端选择过滤的关键回归测试；现有排序和快捷方式 CRUD 测试保持通过。

## Open questions

1. **标签编辑交互。** 编辑器使用 Reka UI `TagsInput` 维护多个自由文本标签，支持 Enter、逗号、失焦和粘贴添加；本期不增加已有标签的自动完成候选框，管理工具条从当前快捷方式实时归纳已有标签。
2. **过滤与拖拽。** 管理页维持全局排序；按标签过滤时禁用拖拽，清除过滤后恢复全量排序，避免将子集提交给完整排序 API。
3. **启用状态变更的并发体验。** 若创建/编辑会话弹窗打开期间，另一客户端禁用了当前快捷方式，后端会拒绝提交；当前沿用通用请求错误提示，后续可增加“快捷方式已禁用或不存在，请重新选择”的专用提示及刷新。

## Decisions

- 采用 `icon` 字符串字段作为图标占位，不在本期实现其编辑、呈现或业务使用，也不绑定图标库或接受外部图片/SVG。
- 采用 `enabled` 正向布尔语义；为处理新旧 Agent/Web 混合版本，协议更新必须具有字段 presence，前端将缺失状态解释为启用，数据库默认值为启用。
- 禁用约束同时在前端选择器和后端会话创建/编辑路径执行。
- 采用 `tags` 多值自由文本标签，以 JSON 数组保存在快捷方式行的 `tags_json` 列中；不建立标签表。
- 管理页使用卡片上方工具条和控件按标签过滤，而不是按标签分区或改变排序模型。
- `last_used_at` 使用 SQLite `TEXT NULL`、MySQL `DATETIME(6) NULL` 和 protobuf `Timestamp` 表示；零值/NULL 表示尚未使用，只存在于 `Shortcut` 响应，不加入创建或更新请求。

## Risk

- `proto3 bool` 缺失时默认 `false`，会让旧 Agent 的响应被新 Web 误判为禁用；必须使用可区分“未提供”的协议设计，或等价地以默认启用的兼容映射解决。
- 当前会话注册表只接收命令和快捷方式快照，不查询快捷方式；为后端强制禁用校验引入快捷方式读取依赖时，必须避免业务层循环依赖并保持本地/云端统一行为。
- 过滤后的拖拽若仍调用全量排序接口，可能造成隐藏项目顺序丢失；首期应明确禁止或重建完整顺序。
- `icon` 字符串虽在本期只做持久化占位，仍不得被当作动态组件名、DOM 内容或其他可执行/可渲染资源处理。
- 标签自由文本需要集中规范化（去除首尾空白，空值表示无标签）；是否大小写折叠由后续明确决策决定，首期建议按规范化后的精确值匹配。
