# 命令快捷方式

最后修改时间: 2026-07-13 22:56:32

Review status: Accepted

## Flow mode / Stage

标准模式 / standard；需求 / Requirement 已接受，当前进入验证 / Verification。

## Background

当前新建会话仅直接填写初始命令。对经常启动的工具或工作流（例如 `ccs run c1`、`codex --dangerously-bypass-approvals-and-sandbox -c xxxx`、`cmd`）而言，用户需要反复输入完整命令，既低效也容易产生拼写或参数差异。

会话已经具有持久化的命令与运行记录模型；停止后的会话当前只能进行有限编辑，不能按与新建会话一致的方式调整其后续启动命令。需要在不改变终端原始命令执行语义的前提下，引入可管理、可复用的命令快捷方式。

## Goal

1. 提供持久化的命令快捷方式（Shortcut），每个快捷方式包含名称、原始命令文本和可选描述。
2. 在会话列表左下角的设置入口中增加快捷方式管理入口，并提供独立的快捷方式列表页面或视图。
3. 快捷方式列表使用卡片展示，并通过模态窗完成创建、编辑和删除等 CRUD 操作；卡片本身承担查看信息的职责。
4. 新建会话默认基于某个快捷方式创建，用户也可以切换回直接输入命令；无论来源为何，最终创建会话仍提交并执行一段原始命令文本。
5. 已停止的会话可以编辑名称与命令，交互和新建会话一致；其工作目录必须只读，不能通过编辑改变。
6. 快捷方式数据通过项目既有 migration/repository 体系持久化；开发阶段允许反复修改尚未发布的 migration。

## Non-goal

1. 不实现快捷方式的参数模板、变量插值、环境变量覆盖、条件执行或脚本编排。
2. 不将快捷方式绑定到特定 workspace、目录或 shell；快捷方式属于当前本地 Agent/设备的数据，不在 Cloud 账户的多个设备间同步。
3. 不改变 PTY 的命令解析、原始命令传递、交互输入或终端 WebSocket 协议。
4. 不改变运行中的会话；运行中的会话不得通过本功能修改命令或目录。
5. 不实现快捷方式分组、标签、导入导出、共享或权限协作。
6. 不承诺迁移历史版本的外部数据；仅通过本轮新增 migration 建立新存储结构。

## User scenarios

### Scenario 1：管理快捷方式

1. 用户在会话列表左下角点击设置按钮。
2. 用户从设置菜单进入“快捷方式”入口。
3. 系统展示快捷方式卡片列表，每张卡片展示名称、完整命令和非空描述。
4. 用户可通过模态窗新建快捷方式，填写名称、命令和可选描述。
5. 用户可通过模态窗编辑已有快捷方式；保存后卡片内容即时更新。
6. 用户可通过确认模态窗删除快捷方式；删除后该快捷方式不再可用于新建会话。

### Scenario 2：拖拽排序快捷方式

1. 用户在快捷方式卡片网格中直接拖动卡片主体改变位置，不显示专用拖拽手柄。
2. 卡片上的编辑、删除按钮仍保持独立点击交互，不会发起拖拽。
3. 拖动结束后，系统提交当前设备完整的快捷方式 ID 顺序，并以服务端返回的规范顺序更新页面。
4. 刷新页面，或从 Cloud 打开同一在线设备时，顺序保持一致；不同设备互不影响。
5. 新建快捷方式追加到当前列表末尾；编辑快捷方式内容不改变其已有位置。
6. 排序请求失败时，页面恢复拖动前顺序、提示错误，并重新读取服务端顺序。

### Scenario 3：统一拖拽反馈与树节点光标

1. 所有既有可排序界面——工作区列表、工作区内会话树、工作台标签和快捷方式卡片网格——在拖动时使用同一套经典反馈语义：原位置/落位保留稳定尺寸的虚线 ghost，占位两侧元素随 `150ms` 动画挤占位置，被拾取元素和随指针移动的元素分别有明确的 chosen 与浮层 dragging 状态。
2. ghost 使用主题变量表达强边框、虚线、弱化表面和弱化文字；chosen 使用 hover 表面与细 ring；dragging 使用 active 表面、强边框和浮层阴影。各表面可按树行、标签或卡片的几何结构细化，但视觉语义在浅色、深色主题下保持一致。
3. 左侧会话树维持整行非交互区域可拖动、无可视专用手柄的交互；普通悬浮不显示 `grab` 或 `grabbing` 光标，避免将可点击的树节点误表达为独立抓手。搜索状态禁用排序后，行仍显示普通可点击指针并可选择。
4. 工作区、会话、标签和快捷方式既有的拖拽入口、过滤规则、排序边界和数据路径不因视觉统一而改变：操作按钮仍可点击；会话不可跨工作区；标签关闭按钮不触发拖拽；快捷方式编辑、删除按钮不触发拖拽。

### Scenario 4：使用快捷方式新建会话

1. 用户打开新建会话对话框。
2. 对话框默认选择“快捷方式”方式，用户从快捷方式列表中选择一个条目。
3. 系统将所选快捷方式的命令作为本次会话的初始原始命令；用户仍填写会话名称和工作目录。
4. 用户可切换到“命令”方式，直接填写原始命令文本，不依赖快捷方式。
5. 创建成功后，实际 Session 只保存本次运行采用的命令文本，不因快捷方式后续被修改或删除而改变历史会话行为。

### Scenario 5：编辑停止的会话

1. 用户选择一个已停止的会话并进入编辑操作。
2. 系统展示与新建会话一致的名称、命令来源/快捷方式选择和直接命令输入交互。
3. 会话当前工作目录显示为只读，用户可以查看但不能编辑。
4. 用户修改名称或命令并保存后，下一次 rerun 使用更新后的命令。
5. 用户尝试编辑运行中的会话时，系统不提供该编辑能力或返回明确的不可编辑结果。

### Scenario 6：Cloud 与 Local 一致使用

1. Local 模式用户管理快捷方式、创建和编辑本地设备会话。
2. Cloud 模式用户对已连接设备执行等价操作。
3. 两种模式复用相同的快捷方式数据模型、输入约束和会话编辑语义；Cloud 路径仍受目标设备在线状态约束。

## Acceptance

### 数据与迁移

- [ ] 新增快捷方式数据模型，至少包含稳定 ID、名称、原始命令、可空描述、创建/更新时间及必要归属字段。
- [ ] SQLite 与 MySQL 均有对应 migration 和 repository 支持，遵循项目现有 migration 组织方式。
- [ ] 快捷方式的名称与命令为必填；描述可为空或缺省。
- [ ] 命令以原始文本持久化和返回，不在快捷方式 CRUD 边界拆分为 argv 或重新拼接。
- [ ] 开发阶段可安全地反复调整尚未发布的 migration；实现不得额外引入与当前 migration 策略冲突的兼容分支。

### 快捷方式管理界面

- [ ] 会话列表左下角设置按钮可进入快捷方式管理入口。
- [ ] 快捷方式使用卡片列表展示名称、命令和存在时的描述。
- [ ] 创建、编辑和删除均通过模态窗完成；卡片直接展示信息，不提供独立查看详情模态窗；删除必须要求显式确认。
- [ ] 创建、编辑、删除成功后列表与选择器同步刷新；失败时显示可理解的错误，不保留误导性的乐观状态。
- [ ] 空列表有明确空状态，并提供创建入口。
- [ ] 用户可通过直接拖动快捷方式卡片主体调整顺序；编辑和删除按钮不触发拖动。
- [ ] 排序按设备持久化：刷新与访问同一设备的 Cloud 页面保持顺序，不同设备相互隔离。
- [ ] 新建快捷方式追加到末尾，编辑不改变位置；排序失败后前端恢复拖动前顺序并显示错误。
- [ ] 后端拒绝非完整、重复、未知或跨设备的 ID 排列，且拒绝时不改变原顺序。

### 拖拽交互一致性

- [ ] 工作区、会话、标签和快捷方式卡片的 Sortable 均提供 ghost、chosen、dragging 三态；ghost 保持虚线的稳定占位，周围元素以既有动画挤占位置。
- [ ] 三态使用一致的主题变量语义：ghost 为虚线与弱化表面，chosen 为 hover 表面与细 ring，dragging 为 active 表面、强边框与浮层阴影；浅色/深色主题均可辨识。
- [ ] 左侧会话树继续以整行非交互区域拖动、无专用可视手柄，但正常悬浮不显示 `grab`/`grabbing` 光标；搜索禁用排序时仍可选择并显示普通可点击指针。
- [ ] 统一视觉反馈不改变既有数据和交互边界：工作区/会话的受控排序、会话跨工作区禁令、操作控件过滤、标签关闭、快捷方式按钮过滤及其持久化/失败回滚均保持原状。

### 新建与编辑会话

- [ ] 新建会话默认使用“快捷方式”，并可在“快捷方式”和“直接命令”之间切换。
- [ ] 选择快捷方式后，会话创建请求使用该快捷方式当时的原始命令文本。
- [ ] 切换到直接命令后，用户可以输入任意现有系统允许的原始命令文本。
- [ ] 不能以空快捷方式、空名称或空命令创建会话。
- [ ] 仅停止的会话可编辑名称和命令；其工作目录在编辑表单中展示但只读。
- [ ] 编辑会话与新建会话复用一致的命令来源选择体验，保存后不启动或重启该会话。
- [ ] 快捷方式的后续编辑或删除不追溯修改既有 Session 或 SessionRun 已保存的命令。

### 兼容与质量

- [ ] 现有直接输入命令的新建会话流程继续可用。
- [ ] 快捷方式、会话创建和停止会话编辑的 API、repository 与关键前端交互具有业务语义明确的测试。
- [ ] Local 与 Cloud 的 API contract 和错误行为保持当前运行时访问边界，不绕过 tunnel / 权限检查。

## Open questions

暂无需要用户确认的未决事项。

已确认的边界将在 Plan / 计划阶段据此落实：

1. 快捷方式为当前本地 Agent/设备的数据，不在同一 Cloud 用户的多台设备之间同步。
2. 新建会话默认使用快捷方式；用户可切换为直接命令。
3. Session 仅保存命令文本快照，不保存 shortcut ID；快捷方式允许在被历史会话使用后删除。
4. 卡片直接承担查看职责，不提供独立的查看详情模态窗。

## Decisions

- 快捷方式是一段原始命令文本，不是结构化 argv、shell script 模板或自动化工作流。
- 快捷方式以设备级显式顺序持久化；卡片主体可直接拖动，不添加专用拖拽手柄。
- 工作区、会话、标签与快捷方式统一采用 ghost、chosen、dragging 三态的 Sortable 反馈；各组件以自身命名空间实现同一视觉语义，不抽取会跨表面耦合的全局拖拽样式。
- 会话树的直接拖动不以 `grab`/`grabbing` 光标表示抓手；不改变整行非交互区域拖动、搜索禁用或交互控件过滤的既有语义。
- 快捷方式至少包含名称、命令和可选描述。
- 快捷方式属于当前本地 Agent/设备的数据；Local 与访问同一设备的 Cloud 页面共享该设备列表，但不在多设备间同步。
- 管理入口从会话列表左下角设置按钮进入，列表采用卡片表达；卡片直接展示信息，不单独提供详情查看模态窗，创建、编辑和删除确认使用模态窗。
- 新建会话默认使用快捷方式，并可切换到直接命令；编辑停止会话复用相同命令来源选择体验。
- 已停止会话的目录是只读字段；运行中的会话不允许编辑。
- 会话保存的是命令快照，不与快捷方式保持动态关联；允许删除曾被会话使用的快捷方式。
- 数据库存储通过 migration 引入，开发阶段允许反复调整未发布 migration。
- 标准模式本轮跳过独立 Spec，下一阶段进入 Plan / 计划。

## Risk

1. **执行安全风险**：快捷方式会降低高权限或危险命令的重复执行门槛；系统应保持现有命令执行权限和本机/Cloud 授权边界，不能因快捷方式绕过验证或增加自动执行。
2. **数据归属风险**：快捷方式明确为设备本地数据；Cloud 页面必须按目标设备访问对应列表，不能误实现为 Cloud 账户全局列表。
3. **会话状态竞争风险**：编辑与 rerun/stop 并发时可能导致命令或状态覆盖。编辑 API 必须仅接受停止状态，repository 或应用层需要以当前状态作为前置条件。
4. **迁移风险**：SQLite/MySQL schema、时间及可空描述处理必须一致；虽允许开发期反复修改 migration，但发布后的 migration 不能重写。
5. **交互复杂度风险**：新增模式切换不应让普通直接命令用户多出不必要步骤，编辑表单与创建表单应尽可能共用状态、校验和错误呈现。
6. **Cloud 在线风险**：Cloud 模式下的创建和停止会话编辑仍需要目标 Agent 可处理实时请求，离线行为需要沿用当前明确错误策略。
7. **拖拽回归风险**：本轮只调整 Sortable 状态类、样式与会话树光标；不得改变受控排序数据源、API 请求、跨工作区禁令、按钮过滤或快捷方式失败回滚。组件 DOM 拖拽自动化尚未建立，需在真实 Local 或 Cloud runtime 页面人工检查四个表面的三态反馈、按钮可用性和两种主题下的对比度。
