# 引入 Air 为后端提供热加载
最后修改时间: 2026-06-20 11:20:04

Review status: Accepted

## Background

当前项目后端为 Go 服务。开发过程中如果每次修改后端代码都需要手动停止、重新构建和启动服务，会降低本地开发反馈效率。

## Goal

- 为后端本地开发引入 `air` 热加载能力。
- 引入 `justfile` 作为项目本地开发命令入口。
- 提供清晰、可执行的本地启动入口，使开发者可以通过 `just` 命令启动后端热加载。
- 保持现有后端构建、测试和生产运行方式不受影响。

## Non-goal

- 不改变后端业务逻辑、API 行为或运行时配置语义。
- 不引入前端热加载改造。
- 不调整部署、生产镜像或线上启动流程，除非项目现有开发入口必须同步声明。
- 不自动安装全局工具；如需 `air`，只记录或通过项目命令引用其安装/运行方式。

## User scenarios

- 开发者修改 Go 后端代码后，后端服务自动重新构建并重启。
- 开发者可以通过 `justfile` 中的命令发现并运行后端热加载命令。
- 未安装 `air` 或 `just` 时，开发者能从配置或文档中判断需要安装的工具。

## Acceptance

- 仓库中存在适用于后端的 Air 配置，例如 `.air.toml` 或等价项目约定配置。
- 仓库根目录存在 `justfile`，并提供至少一个明确的后端热加载启动入口。
- Air 配置的 build/run 命令与当前 Go 后端入口匹配。
- 热加载配置避免监听明显不必要的目录，例如 `.git`、前端构建产物、临时产物等。
- 现有测试或可用的基础验证命令通过，或明确记录无法运行的原因。

## Open questions

- 项目当前是否已有统一开发命令入口（如 `Makefile`、`justfile`、README 或 npm scripts）需要优先复用，需要在实现阶段读取确认。
- 后端主程序入口和默认运行参数需要以现有代码为准确认。

## Decisions

- 用户已要求“也需要引入 justfile，开始实现”，需求状态更新为 `Accepted` 并进入 Implementation / 实现。
- 优先最小化变更：只添加 Air 热加载配置和 `justfile` 开发命令入口，不改变后端业务代码。

## Risk

- 如果当前项目已有多个后端启动方式，Air 配置可能需要选择一个默认入口；实现阶段应以现有项目约定为准。
- 如果 `air` 未作为项目依赖固定版本，不同开发者本机安装版本可能存在行为差异；可在文档或命令说明中提示安装方式。
