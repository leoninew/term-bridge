# 前端引入 i18n
最后修改时间: 2026-06-20 13:46:08

Review status: Accepted

## Background

当前前端 UI 文案主要硬编码在 Vue 组件和少量 API error prefix 中，既有英文文案，也有少量中文文案。随着 workspace/session tree、reka-ui 模态窗、toast 和终端工作台交互增多，需要引入前端 i18n 机制，便于后续统一切换语言和维护文案。

## Goal

1. 为 `web` 前端引入 i18n 基础设施。
2. 至少支持两种 locale：
   - `zh-CN`
   - `en-US`
3. 将主要 UI 可见静态文案迁移到 i18n message：
   - workspace/session sidebar 空状态、搜索 placeholder、按钮 aria-label。
   - App 主工作台空状态、footer label、dialog title/description/button 文案。
   - toast title、表单校验提示、常见操作错误前缀。
4. 提供统一的翻译调用方式，供 Vue template 和 script setup 中复用。
5. 默认 locale 为 `zh-CN`。
6. 在左下角设置区域添加语言切换入口，使用合适的 reka-ui 组件实现。
7. 保持现有功能行为不变：创建 session、重命名、删除、workspace 删除、workspace 排序、terminal history/attach 均不因 i18n 引入而改变。

## Non-goal

1. 不翻译后端返回的业务数据，例如 workspace name、session name、command、cwd、path。
2. 不翻译后端返回的动态 error message；前端自定义 prefix/title 可纳入 i18n。
3. 不调整后端 API、错误结构或配置文件。
4. 不引入复杂的运行时语言包加载、远程翻译或翻译管理平台。
5. 不要求持久化用户语言偏好到后端；如需持久化，优先使用前端本地存储。

## User scenarios

1. 开发者新增 UI 文案时，可以通过统一 i18n message key 添加中英文文案。
2. 用户进入前端时，默认看到 `zh-CN` UI 文案。
3. 用户可以从左下角设置区域打开语言切换入口，在 `zh-CN` 与 `en-US` 间切换。
4. 当前已有 workspace/session 操作流程继续可用，不因为文案迁移改变交互。

## Acceptance

- [ ] 引入 `vue-i18n` 依赖，并在 Vue app 中注册 i18n 实例。
- [ ] 存在 `zh-CN` 与 `en-US` 两套基础 message。
- [ ] 默认 locale 为 `zh-CN`。
- [ ] 左下角设置区域提供语言切换入口，并使用合适的 reka-ui 组件。
- [ ] `App.vue` 中主要可见静态 UI 文案迁移到 i18n。
- [ ] `WorkspaceSessionSidebar.vue` 中主要可见静态 UI 文案和 aria-label 迁移到 i18n。
- [ ] 前端 API client 中面向 UI 的错误 prefix/title 如继续存在，应有清晰策略：迁移到 i18n 或保留为技术错误前缀并在风险中说明。
- [ ] 不翻译 workspace/session 用户数据和后端动态错误 message。
- [ ] `yarn --cwd web typecheck` 通过。
- [ ] `yarn --cwd web lint` 通过。

## Decisions

- 使用轻量模式 / light。
- 使用 `vue-i18n`，允许新增依赖并更新 lockfile。
- 默认 locale 为 `zh-CN`。
- 在左下角设置区域添加语言切换入口，使用 reka-ui 的合适组件实现。
- 本轮只处理前端 i18n，不改后端。
- 语言范围限定为 `zh-CN` 与 `en-US`。
- 动态用户数据和后端动态错误信息不翻译。

## Risk

1. `vue-i18n` 会新增依赖并更新 lockfile；这会扩大 diff，但维护性更好。
2. 当前工作树中已有前端 tree actions 和 workspace 排序改动，i18n 改动可能与这些未提交 UI 文案变更交织；实现前应确认提交边界。
3. 大量文案迁移容易遗漏 aria-label、placeholder、toast title 或脚本中的 error prefix，需要通过 grep 和人工核对补充。
4. 语言切换入口放在左下角设置区域，可能需要调整该区域当前简化的 footer 结构。
