# 会话生命周期状态主题色

最后修改时间: 2026-07-13 11:41:58

Review status: Accepted

## Flow mode / Stage

轻量模式 / light；需求 / Requirement 已接受，当前进入实现 / Implementation。

## Background

`/sessions` 当前在左侧会话节点、底部状态栏和 Tab 页标题中展示生命周期状态（`running`、`stopped`、`failed`），但缺少统一、可辨识的视觉语义。用户需要通过主题色快速判断会话状态，而不应仅依赖状态文本。

## Goal

为三个既有会话状态提供一致的主题色，并应用到以下 UI：

1. 左侧会话节点。
2. `/sessions` 底部状态栏中的状态文本。
3. 会话 Tab 页标题。

状态语义暂定如下：

- `running`：成功 / 活跃色。
- `stopped`：中性 / 静止色。
- `failed`：中性 / 静止色，与 `stopped` 相同。

## Non-goal

1. 不增加、删除或重命名生命周期状态，也不改变状态转换规则。
2. 不改变命令来源（快捷方式、直接命令、启动命令）的视觉语义。
3. 不以状态主题色替代状态文字；颜色仅作为额外辨识信号。
4. 不在本需求中重构会话导航、Tab 布局或状态持久化模型。

## User scenarios

1. 用户在左侧会话树中通过状态色快速识别正在运行、已停止和失败的会话。
2. 用户查看底部状态栏时，状态文本与左侧节点使用相同语义色。
3. 用户同时打开多个会话 Tab 时，能够从标题区域辨别每个会话状态。
4. 使用不同主题或辅助显示方式时，状态文字仍保留，避免仅靠颜色传达状态。

## Acceptance

- [ ] `running` 使用活跃主题色，`stopped` 与 `failed` 共用固定的中性主题色。
- [ ] 左侧会话节点、底部状态栏、Tab 页标题均使用同一套状态映射。
- [ ] 三处 UI 均保留状态文本或其他非颜色信息，不只依赖颜色传意。
- [ ] 现有选中、悬浮、禁用和截断行为不被状态样式破坏。
- [ ] 状态样式配置集中管理，不在三个 UI 分散硬编码颜色判断。
- [ ] 相关前端检查与已有测试通过。

## Open questions

暂无需要用户确认的未决事项。实现时将优先复用现有设计令牌；若系统尚无合适的成功、危险或中性色令牌，再在主题层补足最小集合。

## Decisions

- 生命周期状态来源继续使用现有 `SessionSummary.lifecycle_state`，不新增 API 字段。
- 显示值未知或缺失时采用现有默认文字与中性样式，不伪造为任一已知状态。
- 颜色映射应由前端共享 helper 或集中样式定义提供，确保三个区域一致。

## Risk

- 深浅主题下直接使用固定色值可能造成对比度不足或与选中态冲突，因此必须优先采用主题 token。
- 左侧节点和 Tab 标题可能已有选中/激活色；状态色应限定到状态标签、图标或指示元素，避免覆盖主要交互状态。
- 实际 UI 结构可能将 Tab 标题或节点状态封装在多个组件中，实施前需定位全部渲染点，避免只覆盖局部。

## User review notes

- 用户于 2026-07-13 要求为会话页面的左侧会话节点、底部状态栏和 Tab 页标题增加按生命周期状态区分的主题色，并要求使用 SpecFlow 记录任务。
- 用户于 2026-07-13 要求移除失败红，使 `failed` 与 `stopped` 共用中性灰。
