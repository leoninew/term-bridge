# 本地首页快捷方式卡片需求

最后修改时间: 2026-07-11 16:02:28

Review status: Accepted

## Background

快捷方式已通过 `/shortcuts` 独立页面管理，但本地模式首页此前只展示设备概览与工作区列表。用户需要在进入本地工作台后快速确认当前设备可复用的命令，并能进入完整的快捷方式管理页面。

## Goal

在本地模式首页新增只读“快捷方式”卡片：

1. 卡片标题显示“快捷方式”。
2. 标题右侧显示“更多 / More”入口，跳转至既有 `/shortcuts` 页面。
3. 卡片以响应式紧凑网格展示最多四个快捷方式：宽屏四列，每项展示名称与紧凑的常规字体命令预览；视口不足时自动降列以保持可读性。
4. 工作区卡片展示最多五个工作区。
5. 卡片分别呈现加载中、加载失败、空列表与有数据状态。
6. 快捷方式加载和工作区加载彼此隔离；任一列表请求失败不得阻止另一卡片正常展示。

## Non-goal

- 不修改快捷方式 CRUD、排序、校验或后端 API 契约。
- 不在首页提供编辑、删除、创建或直接运行快捷方式的操作。
- 不修改既有 `/shortcuts` 管理页面或路由定义。
- 不为首页引入分页、搜索、数量限制或新的共享卡片组件。

## User scenarios

1. 本地用户打开首页，在快捷方式卡片中查看所有已保存的快捷方式名称和命令摘要。
2. 用户点击“更多”后进入 `/shortcuts`，进行完整的快捷方式管理。
3. 当前设备没有快捷方式时，用户看到明确的空状态说明。
4. 快捷方式加载失败时，用户看到该卡片的失败提示，同时仍可使用工作区卡片；反之亦然。

## Acceptance

- [ ] 本地首页出现“快捷方式 / Shortcuts”卡片。
- [ ] 卡片标题右侧的“更多 / More”链接使用既有 `local-shortcuts` 路由并到达 `/shortcuts`。
- [ ] 首页工作区最多显示前五项，快捷方式最多显示前四项；数据源和后端列表接口保持全量、无分页契约。
- [ ] 宽屏时快捷方式以四列紧凑网格展示；较窄视口自动降列。
- [ ] 首页每个快捷方式以紧凑标题 role 的名称和常规 `text-sm` 单行截断命令预览呈现，不卡片内提供编辑或删除按钮。
- [ ] `/shortcuts` 宽屏时同样以四列响应式网格展示，命令正文不使用等宽字体。
- [ ] 加载、空、错误和有数据状态均有可见反馈。
- [ ] 快捷方式和工作区请求在身份初始化后独立执行，任一加载失败不会影响另一方的已加载数据或状态。
- [ ] 中文与英文都提供“更多 / More”文案。

## Open questions

暂无需要用户确认的未决事项。

## Decisions

- 复用既有 `listShortcuts()`、`Shortcut` 类型和 `local-shortcuts` 路由，不新增前后端契约。
- 首页与 `/shortcuts` 均采用响应式网格：宽屏四列，较窄视口自动降列；首页不复用带编辑/删除操作的 `ShortcutCard` 管理组件。
- 命令文本是产品 UI 正文而非代码编辑器内容：首页命令预览、`/shortcuts` 卡片命令与相关标题均使用项目既有 `text-sm` 层级；名称使用 `text-sm font-semibold` 紧凑标题 role，普通命令和描述保持常规字重。
- 首页在接收全量列表后按既有排序截取前五个工作区和前四个快捷方式；不新增分页字段、后端查询限制或 API 契约，完整列表仍由 `/sessions` 与 `/shortcuts` 管理页面展示。

## Risk

- 组件级自动化测试基础设施尚未配置；本次以类型检查、lint、构建、现有单元测试与手工页面验证为主。
- 当前工作区可能存在与本功能无关的预先存在格式问题或未跟踪文档，后续验证时需按实际 diff 区分。
