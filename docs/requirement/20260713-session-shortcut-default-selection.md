# 会话快捷方式默认选择与恢复

最后修改时间: 2026-07-13 09:32:50

Review status: Accepted

## Flow mode / Stage

轻量模式 / light；需求 / Requirement 已接受，当前进入实现 / Implementation。

## Background

会话命令控件支持在“快捷方式”和“直接命令”两种来源之间切换，但当前切换到直接命令会清空已选快捷方式 ID。新建会话进入快捷方式模式时也不会自动选中可用项，导致用户必须额外选择，且切回快捷方式时无法恢复原选择。

## Goal

1. 新建会话打开时，快捷方式列表非空则自动选中当前列表第一个快捷方式，并使用其原始命令文本。
2. 编辑会话从直接命令切入快捷方式模式时，快捷方式列表非空则自动选中第一个快捷方式。
3. 用户已选择快捷方式后，在“快捷方式 → 直接命令 → 快捷方式”间切换时恢复此前选择；若此前快捷方式已不存在，则回退到当前列表第一个快捷方式。

## Non-goal

1. 不改变快捷方式的持久化顺序、排序规则、API 或数据模型。
2. 不改变会话保存的命令快照语义，也不为 Session 持久化 shortcut ID。
3. 不新增组件测试基础设施；本次使用既有 Vitest composable 测试方式验证状态规则。

## User scenarios

1. 用户打开新建会话窗口，看到快捷方式模式及第一个已选快捷方式；提交时使用该快捷方式的原始命令。
2. 用户在编辑停止会话窗口中从直接命令切到快捷方式，系统选择第一个快捷方式；选择其他快捷方式后往返切换来源，返回该快捷方式。
3. 用户的已选快捷方式在切换期间被删除，返回快捷方式模式时系统选择当前可用列表的第一个条目。
4. 快捷方式列表为空时，模式切换不清空已有直接命令文本，快捷方式控件保持不可选。

## Acceptance

- [ ] 新建会话在快捷方式非空时默认选中第一个条目，并将其原始命令作为创建命令。
- [ ] 编辑会话首次打开仍使用直接命令与既有会话命令；切入快捷方式模式后按默认选择规则工作。
- [ ] 直接命令模式不清除记忆的快捷方式 ID 或现有命令文本。
- [ ] 返回快捷方式模式时优先恢复仍有效的选择；无效或缺失时回退到第一个当前快捷方式。
- [ ] 空快捷方式列表不能删除已有命令文本。
- [ ] 相关状态转换具有业务语义明确的 Vitest 覆盖，且前端测试和类型检查通过。

## Open questions

暂无需要用户确认的未决事项。

## Decisions

- “第一个快捷方式”严格采用运行时 `shortcuts` 数组的现有顺序，不在前端重新排序。
- 快捷方式 ID 是 UI 内存态，用于在来源切换时恢复选择；会话最终仍仅提交原始命令文本。
- 进入快捷方式模式意味着采用该快捷方式当前命令，因此恢复选择时会同步命令文本；进入直接命令模式则不改写命令文本。

## Risk

- 快捷方式列表可能为空或在用户切换来源后发生更新；处理必须避免把直接命令文本清空。
- 记忆的 ID 可能不再位于当前列表，必须以第一个可用快捷方式回退，不能展示失效的空选择。
