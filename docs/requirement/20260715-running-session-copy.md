# 运行中会话复制入口

最后修改时间: 2026-07-15 08:25:54

Review status: Accepted

## Flow mode / Stage

轻量模式 / light；需求 / Requirement 已接受，已完成实现并进入验证 / Verification。

## Background

`/sessions` 页面左侧按工作区展示会话树。运行中的会话仅展示状态点和停止操作，用户若要基于其当前配置再建会话，必须手动打开新建会话窗并重新填写名称、快捷方式或命令。

## Goal

1. 在左侧树的运行中会话节点内，于运行状态标识左侧提供 copy icon 入口。
2. 点击该入口打开现有“新建会话”模态窗，预填被复制会话的名称和命令配置：快捷方式来源恢复其快捷方式/命令，直接命令来源恢复其命令。
3. 预填名称按 `<原名称>_<n>` 生成，其中 `n` 从 1 递增，选择当前前端已知会话树中第一个未使用的候选名称。
4. 用户仍可在模态窗中修改预填内容，并沿用现有创建会话流程提交。

## Non-goal

1. 不新增、修改或调用后端 API，不改变后端会话创建、生命周期或名称约束。
2. 不为停止或失败会话新增复制入口。
3. 不改变现有全局或工作区级“新建会话”入口的默认名称与快捷方式选择规则。
4. 不实现跨浏览器标签、跨用户或服务端并发下的名称唯一性保证；本次仅基于当前前端内存中的工作区树计算候选名称。

## User scenarios

1. 用户在左侧树看到运行中的会话，在其运行状态点左侧点击 copy icon，打开已预填配置的新建会话窗。
2. 被复制会话来源为快捷方式时，模态窗保持快捷方式来源，并显示对应快捷方式及其命令；若快捷方式当前不再可选，仍保留该会话的原始命令，用户可改为直接命令后创建。
3. 被复制会话来源为直接命令时，模态窗显示直接命令来源和原始命令。
4. 当前树中已存在 `构建_1`、`构建_2` 时，复制名称为“构建”的会话预填 `构建_3`；若仅存在 `构建_2`，则预填 `构建_1`。

## Acceptance

- [ ] 仅 `running` 会话节点展示 copy icon，且视觉位置在运行状态标识左侧。
- [ ] 点击 copy icon 不触发会话节点选择，并打开现有新建会话模态窗。
- [ ] 模态窗预填被复制会话的命令来源、快捷方式信息（适用时）和原始命令；用户可继续编辑并使用现有创建逻辑提交。
- [ ] 复制名称严格遵循 `<原名称>_<n>`，从 1 起取当前前端会话树中第一个可用递增序号。
- [ ] 复制会话不改变原会话、工作区树排序、生命周期操作或既有新建入口。
- [ ] 为名称生成与复制草稿预填的状态规则补充业务语义明确的前端测试，并通过相关前端检查。

## Decisions

- 复制入口复用现有 `CreateSessionDialog`、`useCreateSessionDraft` 和创建提交路径，不引入独立“复制会话”后端概念。
- 名称可用性以当前 `workspaceSessions.workspaceTree` 中全部已加载会话名称判断，不限定同一工作区，以降低当前前端可见范围内的重复名称。
- 快捷方式快照仍按既有会话创建契约传递；若快照对应的快捷方式已不可选，预填流程不伪造有效快捷方式选择，保留命令文本供用户切换为直接命令后提交。

## Risk

- 前端树是加载时快照，其他客户端或并发创建可能在提交前占用相同名称；后端当前不强制名称唯一性，本次不扩大到服务端协调。
- 历史或外部数据可能携带不完整的快捷方式快照；预填逻辑必须避免构造无法通过既有表单校验的快捷方式状态。
- 左树会话节点本身有点击选中与拖拽交互，copy icon 需要阻止事件传播，避免误选会话。
