# JWT 认证替换随机 token - 技术规格

最后修改时间: 2026-06-25 16:45:00

## Requirement basis

来源：`docs/requirement/20260625-jwt-auth.md`

当前认证使用随机 32-byte hex token + 内存 session map，存在服务重启丢失全部登录状态的问题。参考 pomelo-orbit 的 JWT（HS256）+ Bearer token 方案进行替换。

## Overview

将认证机制从 cookie-based session 替换为 JWT-based Bearer token。Token 通过 `Authorization` 头传递，服务端无状态验证。

参考实现：`D:\SourceCodes\mywork\pomelo-orbit\backend-go\internal\service\auth\token.go`

## Design decisions

### 1. JWT 结构

```
Header: {"alg": "HS256", "typ": "JWT"}
Payload: {"sub": "<username>", "exp": <unix_timestamp_24h>}
Signature: HMAC-SHA256(header.payload, secret)
```

- `sub`: 用户名（与 pomelo-orbit 不同，pomelo-orbit 用 user ID，这里用 username 因为 TermBridge-go 的 `AuthConfig` 只有 username/password）
- `exp`: 当前时间 + 24 小时

### 2. 密钥管理

- 配置字段：`jwt.secret_key`（新增 `JWTConfig`）
- 必须手动配置，不自动生成
- 启动时验证密钥非空
- **密钥格式**：base64 编码的 32 字节随机字符串（生成方式：`openssl rand -base64 32`），与 pomelo-orbit 一致。不是 Fernet 格式

### 3. Token 传递方式

- 登录返回：`{"access_token": "<jwt>", "token_type": "bearer"}`
- 后续请求：`Authorization: Bearer <jwt>`
- 不再使用 cookie

### 4. 中间件

- 从 `Authorization` header 提取 Bearer token
- 调用 `TokenService.Verify()` 验证签名和有效期
- 失败返回 401

## Interfaces

### POST /api/login

**Request:**
```json
{
  "username": "string",
  "password": "string"
}
```

**Response (200):**
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer"
}
```

**Response (401):**
```json
{
  "code": "unauthorized",
  "error": "Invalid username or password",
  "requestId": "req_..."
}
```

### GET /api/me

**Request Header:** `Authorization: Bearer <jwt>`

**Response (200):**
```json
{
  "authenticated": true,
  "username": "admin"
}
```

**Response (401):**
```json
{
  "code": "unauthorized",
  "error": "Invalid token",
  "requestId": "req_..."
}
```

### POST /api/logout

**Request Header:** `Authorization: Bearer <jwt>`

**Response (200):**
```json
{
  "ok": true
}
```

> 注：服务端不维护 session 状态，logout 只需前端清除本地 token。

## Technical questions

1. **Token 存储位置** — localStorage（与 pomelo-orbit 一致），不使用 sessionStorage（标签页关闭即丢失体验差）
2. **401 自动跳转** — 前端响应拦截器捕获 401 后清除 token 并 `router.push('/login')`
3. **密钥格式** — base64 编码的 32 字节随机字符串（生成方式：`openssl rand -base64 32`），与 pomelo-orbit 一致，启动时验证密钥非空
4. **Token 前缀** — 固定 `Bearer`，与 pomelo-orbit 一致

## Risks

- **密钥泄露** — 生产环境必须配置强密钥（32 字节随机字符串，URL-safe base64 编码）
- **XSS** — localStorage 可通过 JavaScript 读取，XSS 可窃取 token。当前项目已有 XSS 风险面，不因此次变更引入新攻击面
- **无状态限制** — JWT 一旦签发无法提前吊销（除非引入黑名单，当前不实现）
- **时钟偏移** — `exp` 验证依赖服务端时钟，极端情况下可能接受过期 token

## Alternatives

### A) 保持 cookie 但改用 JWT 内容

- 将 JWT 放入 cookie 而非 Authorization header
- 优点：HttpOnly 防 XSS
- 缺点：需要处理 CSRF、与 pomelo-orbit 方案不一致
- **不采用**：用户明确要求参考 pomelo-orbit 的 Bearer token 方案

### B) 引入 refresh token

- Access token 短期（1h）+ refresh token 长期（7d）
- 优点：减少频繁登录
- 缺点：增加实现复杂度
- **不采用**：需求明确不实现 refresh token
